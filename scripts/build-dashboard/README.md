# 로컬 빌드 데스크

이 도구는 `SIRIUS_BuildDashboard` 독립 저장소에서 실행합니다. LENS 소스 경로는 `settings.json`의 `lensPath`, 인스톨러는 `installerPath`로 지정합니다. 아래 저장소 루트와 실행 기록 경로는 별도 표시가 없는 한 대시보드 저장소 기준입니다.

저장소 루트의 `Open Build Dashboard.cmd`를 더블클릭하면 서버가 숨김 백그라운드로 실행되고 브라우저가 열립니다. 명령 창은 자동으로 닫힙니다. 이미 실행 중이면 서버를 중복 실행하지 않습니다.

명령어로 실행하려면 저장소 루트에서 다음을 사용합니다. Node.js 22 이상, PowerShell, Git, 기존 .NET 빌드 환경이 필요합니다.

```powershell
.\scripts\start-build-dashboard.ps1
```

브라우저 주소: http://127.0.0.1:4178. 브라우저나 실행용 터미널을 닫아도 백그라운드 서버는 유지됩니다.
현재 Windows 계정의 로그인 시 자동 실행 등록: `.\scripts\start-build-dashboard.ps1 -RegisterStartup -NoBrowser`.
등록 해제: `.\scripts\start-build-dashboard.ps1 -RemoveStartup` (실행 중인 서버는 유지).
서버 코드 수정 후 재시작: `.\scripts\start-build-dashboard.ps1 -Restart -NoBrowser`. 진행 중인 작업이 있으면 재시작을 거부합니다.
자동 실행은 로그인 후 시작하며 브라우저를 열지 않습니다. 서버 로그는 `artifacts/dashboard-server`에 저장합니다.
설정은 이 폴더의 `settings.json` 한 곳에서 변경합니다. 설치 프로그램 저장소 경로, 서명 키 별칭, 포트, Codex 실행 경로, Notion 대상 ID를 지정할 수 있습니다. 비밀 키를 넣지 않습니다.
`codexCommand`가 기본값 `codex.exe`이면 작업 실행 시 PATH를 확인하고, 없으면 `%LOCALAPPDATA%/OpenAI/Codex/bin`의 설치 파일을 자동 탐색합니다. 버전별 폴더는 최근 수정 순으로 확인하며 경로를 고정 저장하지 않습니다. 별도 CLI를 사용하려면 전체 경로를 지정하세요.

메인 화면의 간략한 배포 이력은 `releases.json`에서 관리합니다. 전달일·설명·참조 커밋을 기록하며 Git 태그나 Notion 기록을 변경하지 않습니다. 제품 로고는 LENS의 기존 Branding 리소스를 그대로 읽습니다. 버전 업그레이드가 비활성화되면 제품 카드 아래에 표시된 미커밋 변경 또는 실행 중인 작업 안내를 확인하세요.

배포 · 빌드 기록 영역에서 `Release Notes`와 `빌드 이력` 탭을 전환할 수 있습니다. 빌드 이력에는 대시보드에서 실행한 제품 버전, 시작 커밋, 미커밋 변경 포함 여부, 시각, 상태와 결과 폴더를 표시합니다. 과거 수동 빌드는 추측해서 추가하지 않습니다.

## 빌드

- LENS: `scripts/publish-protected.ps1` → 결과 복사 → `smctl sign --dynamic-auth` → Authenticode 검증 → ZIP 생성. 인스톨러 빌드는 별도로 실행합니다.
- ZIP에는 `SiriusLens/` 최상위 폴더를 포함합니다. 제거 프로그램은 인스톨러에 내장하므로 제품 ZIP에 별도로 넣지 않습니다.
- Installer 단독 빌드: 기존 publish 스크립트로 설치·제거 EXE를 생성합니다. API 설정은 인스톨러 EXE에 내장됩니다. 기존 `publish/`도 스크립트 계약에 따라 갱신됩니다.
- 작업 파일/로그/작업 기록: 대시보드의 `artifacts/dashboard/<작업 ID>/`. ZIP SHA256와 인증서 지문은 `package.json`에 기록합니다.
- LENS 최신 배포 파일은 LENS 저장소의 `publish/SiriusLens/`, `publish/SiriusLens.zip`에 고정됩니다. `publish/build-info.json`에는 버전·커밋·미커밋 변경 여부·소스 지문을 기록합니다.
- LENS 성공 빌드는 `settings.json`의 `lensArchivePath`(기본 `D:/SIRIUS_LENS/releases`) 아래 작업 ID별로 보관합니다. 서명된 폴더·ZIP·빌드 정보와 비공개 진단 자료를 보관하며, 외부 배포 시 `private-diagnostics`는 제외합니다.
- D드라이브 보관이 완료된 다음 최신 `publish`를 교체합니다. 교체 중에만 이전 파일을 롤백용으로 유지하고, 성공 후 C드라이브의 이전 publish 백업·이번 작업의 배포 복사본·보호 빌드 중간 폴더를 삭제합니다.
- Installer는 저장소의 `publish` 최신 EXE만 사용하고, 성공 시 이번 게시 임시 폴더를 삭제합니다. 대시보드 작업별 설치 파일 복사본은 만들지 않습니다.
- 작은 작업 이력·로그는 C드라이브 `artifacts/dashboard`에 남습니다. 실패한 작업의 진단용 파일 및 기존에 쌓인 과거 파일은 자동 삭제하지 않습니다. 이 정책은 대시보드를 통한 빌드에 적용됩니다.
- 서명 인증은 사용자가 완료해야 할 수 있습니다. 실패하면 ZIP을 생성하지 않습니다. 패키지 생성은 실제 WPF 화면 검증이나 서버 업로드를 의미하지 않습니다.
- 빌드 중 소스가 바뀌면 실패로 표시합니다. 해당 결과를 배포하지 말고 다시 빌드하세요.

## 커밋과 Notion

실행 기록은 최신순/오래된 순으로 정렬하고 전체/완료/오류/실행 중으로 필터링합니다. 오류에는 일부 완료와 중단 기록도 포함하며, 자동 갱신 중 선택 조건을 유지합니다.

Notion 제목·본문은 “버튼 배치”처럼 간결한 명사형으로 작성합니다. 비어 있는 `작업 시작`에는 대시보드 최초 실행일(한국 시간)을 기록합니다. 이미 입력된 날짜는 보존하고 재시도에서도 최초 실행일을 유지합니다. 실제 개발 착수일을 추정하지 않으며 기존 기록을 일괄 수정하지 않습니다.

Codex CLI 로그인과 Notion OAuth 연결이 필요합니다. `Notion 연결` 버튼은 공식 `https://mcp.notion.com/mcp` 서버를 `lens-notion` 이름으로 등록하고 인증합니다. Codex 데스크톱의 연결과 CLI OAuth는 별개일 수 있습니다.

커밋 버튼은 현재 소스 변경을 검토·검증한 뒤 커밋하고 기존 Notion 업무 DB에 설명과 제품/버전 관계를 기록합니다. 담당자를 입력하지 않으면 인증된 Notion 사용자를 확인해서 사용합니다. 확인할 수 없으면 중단합니다. 관련 이슈 링크는 선택 사항입니다.

버전 업그레이드는 깨끗한 작업 폴더에서 실행합니다. 마지막 버전 태그 이후 변경을 요약해 버전과 기존 언어별 업데이트 사항을 수정·검증·커밋하고 Notion 버전과 업무를 연결합니다. Installer 자체 버전은 별도로 유지하되, Notion 업무는 작업 시작 시 확인한 SIRIUS LENS 버전의 기존 레코드에 연결합니다. 일치하는 레코드가 없거나 여러 개이면 커밋 전에 중단하며 별도 Installer 버전을 만들지 않습니다. 기존 Notion 기록은 자동 변경하지 않습니다. 빌드/배포가 끝난 것으로 표시하지 않으며, 태그·푸시·업로드는 자동 실행하지 않습니다.

메인 화면 상단의 공통 Model·Reasoning에서 모델과 추론 강도를 선택합니다. Default는 CLI 설정 모델을 사용하고, 추론 강도 기본값은 Low입니다. 계정에서 지원되는 모델을 선택해야 하며 지원 여부와 비용을 자동 판단하지 않습니다. 선택값은 브라우저에 저장하며 이후 커밋·버전 작업에 적용합니다. 진행 중인 작업과 전역 Codex 설정은 변경하지 않습니다. Notion 재시도는 원래 실행의 모델·강도를 재사용합니다. 빌드·서명과 Notion 연결 인증에는 모델을 사용하지 않습니다.

빌드는 확인 팝업 없이 즉시 실행합니다. 커밋·버전 작업은 입력 확인 팝업을 유지합니다. 현재 작업 영역에는 실행 중인 작업 또는 가장 최근 결과를 표시하고, 로그는 그 아래 펼쳐 봅니다. 실행 중에는 퍼센트를 추정하지 않는 진행바를 표시하고 완료·실패 시 숨깁니다. 이전 작업 기록은 접힌 영역에서 정렬·필터링할 수 있습니다.

Notion 업무 작성 시 작업 시작은 최초 실행일, 작업 종료는 검증된 개발 완료 커밋의 날짜를 한국 시간 기준으로 입력하도록 요청합니다. 재시도에서도 원래 실행·커밋 날짜를 사용하고 기존 날짜는 보존합니다. 두 날짜의 저장 여부와 순서를 재조회해 확인해야 완료로 보고합니다. 완료 목표 날짜는 별도 선택 항목이며, 기존 업무를 일괄 소급 변경하지 않습니다.

현재 작업 상태는 대기·진행·오류·완료로 표시합니다. 완료/오류 결과가 활성 브라우저의 화면에 보이면 확인 여부를 해당 브라우저에 저장합니다. 같은 방문 중에는 결과를 유지하고, 다음 접속 또는 새로고침 시 확인한 최신 결과 대신 대기를 표시합니다. 진행 중이거나 아직 보지 못한 최신 결과는 계속 표시하며 이전 기록은 삭제하지 않습니다. 브라우저 저장소를 지우거나 다른 브라우저를 사용하면 확인 상태가 공유되지 않습니다.
배포 및 빌드 기록의 All/LENS/Installer 필터는 두 탭에 공통 적용됩니다. 기존 제품 미지정 배포 기록은 LENS 기록으로 취급하며, Installer 배포 기록이 없으면 빈 상태를 표시합니다.

CLI는 `--approve-for-me`로 정상적인 샌드박스와 자동 승인 검토를 사용합니다. 정책상 작업이 거절되면 실행 기록에서 사유를 확인하세요. 승인 우회 옵션을 사용하지 않습니다. 연결 실패 시 소스를 바꾸기 전에 중단하도록 지시합니다.

Git와 Notion은 하나의 트랜잭션이 아닙니다. 커밋 후 Notion에서 실패하면 `일부 완료`와 커밋 SHA를 남깁니다. `Notion 재시도`는 그 커밋으로만 연결을 복구하며 다시 커밋하지 않습니다. 서버가 중단된 경우 기존 프로세스 및 Git/Notion 상태를 먼저 확인하세요.

## 검증

```powershell
node --test scripts/build-dashboard/tests/dashboard.test.mjs
node --test scripts/build-dashboard/tests/latest-package.test.mjs
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build-dashboard/tests/package.test.ps1
```
